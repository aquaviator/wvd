# WVD working brief

Purpose: turn in-scope ideas into researched, reusable, verified products and
deploy through existing authorised foundations. Founder: Andy Clarke.

Start with [idea-to-deploy](WVD-IDEA-TO-DEPLOY.md), then the specific product's
current-state/backlog and constitution. Read deeper standards only as needed.

- Engineering authority: [project authority](WVD-PROJECT-AUTHORITY.md).
- Technical baseline: [development standard](WVD-DEVELOPMENT-STANDARD.md).
- Access: [discovery process](WVD-ACCESS-AUTOMATION.md) and factory access registry.
- Reuse: `tools/factory/reuse-catalogue.json`; candidates require current review.
- Websites: [Sites handoff](WVD-SITES-HANDOFF.md).
- Priority products: Salon and Wedding; preserve their release restrictions.
- WVD runtime: [branded workspaces](WVD-BRANDED-WORKSPACES-MVP.md) and exact
  deployment evidence, refreshed before changes. Documentation is not live proof.

One focused workstream per task. Record verified source, outcome, next action and
blockers in the product-owned current-state record. Chat history is supporting
context, not the release ledger. No new paid social-management services. TikTok
is parked; LinkedIn API application is paused. Meta setup is not yet a verified
API connection. Keep unrelated account setup out of coding task packets.
